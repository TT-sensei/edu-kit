# Final Review — edu-doctor

## いつ使うか

教材の作成・変更後、完成扱いにする前に必ず使う。見た目の改善で別の場所が壊れる回帰を防ぐ。

## 最初に確認するもの

1. ユーザーの依頼と保護対象
2. 変更前後の差分
3. 使用した共通資産の正本
4. 対象学年、主要端末、保存の有無

## 使用候補

- ブラウザのコンソールとネットワーク確認
- スマホ、タブレット縦・横、PCの表示確認
- タッチ、マウス、キーボード操作
- `node scripts/verify-repositories.mjs`による共通資産の整合性確認

## 手順

1. 問題文、正答、誤答、単元構成と保護対象を確認する。
2. ホーム→開始→出題→正解→不正解→次問→結果→ホーム→再スタートを通す。
3. namespace、リロード後の保持、古い保存データへの耐性を確認する。
4. 各端末幅で文字切れ、横スクロール、重なり、主要操作を確認する。
5. 音なし、画像失敗、reduced motionでも学習できるか確認する。
6. コンソールエラーと外部参照URLを確認する。
7. API、CSSクラス、音ID、画像パスの実在を正本で確認する。
8. 再利用可能な仕組みを5資産へ還元できるか検討する。

## 完了条件

- 重大な問題が0件。
- 保護対象を意図せず変更していない。
- 基本フローを最後まで通せる。
- 補助機能の失敗で学習本体が停止しない。
- スマホ、タブレット縦・横、PCで主要操作が可能。
- 使用API・CSS・音ID・画像パスが実在する。

重大な問題が1つでもある場合は完成扱いにせず、修正後にこのSkillを最初から再実行する。
