# Create Learning App

## いつ使うか

新しい小学校向けWeb教材を、学習目標と学習行動から設計・作成するときに使う。

## 最初に確認するもの

1. DESIGN-PRINCIPLES.md
2. AI-GUIDE.md
3. 学年・教科・単元・身につけたい力
4. 1回の問題数または1回のシミュレーション単位
5. 保存の要否と利用端末
6. 問題形式、つまずいたときの脱出口

## 使用候補

- edu-components：出題、判定、進行、保存
- edu-effects：学習UIと必要最小限の演出
- sounds-recipe-：効果音が学習を補助する場合だけ
- edu-assets：学習上意味のある報酬が必要な場合だけ
- navi-character-：案内・励ましが必要な場合だけ

## 手順

1. 身につけたい力を1文で定義する。
2. 子どもが繰り返す行動を定義する。例：見る→考える→答える→反応を見る→次へ。
3. 問題形式またはシミュレーターの循環を決める。
4. 開始画面で単元・モード・段などを必要な範囲で選べるようにする。
5. 1回の問題数・終了条件・次に進む方法を決める。
6. edu-componentsから必要な部品だけを選び、正本で実在を確認する。
7. 不正解や長い迷いの後に、ヒント・解説・答えを見る・再挑戦などの脱出口を設計する。
8. 保存が必要な場合は教材固有namespaceを決め、StorageManagerを使う。
9. 学習骨格、文字、式、観察対象、主要操作を先に作る。
10. タブレット横向きの1画面に収まるように整える。
11. 学習骨格の完成後にUI、音、報酬、ナビキャラを選ぶ。
12. HTML/CSS/Vanilla JSでGitHub Pagesから直接動く構成にする。
13. final-reviewを実行する。

## 完了条件

- 最初の画面から、何を学ぶか・どこを押すか・選択中の状態が分かる。
- 問題・観察・主要操作がタブレット横向きの基本1画面に収まる。
- 教師の追加説明なしでも基本操作が理解できる。
- 正誤だけでなく次の行動が分かる。
- 答えを見た場合を正答・マスター達成として記録していない。
- シミュレーターは条件変更が現象へ反映され、リセットして再試行できる。
- ご褒美やキャラクターより問題・観察・操作が主役になっている。
- PC・タブレット・スマホで主要操作が可能。
- 使用API・クラス・ID・URLの実在を正本で確認済み。
