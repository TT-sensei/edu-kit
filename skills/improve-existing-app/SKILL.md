# Improve Existing App

## いつ使うか

既存教材の学習内容と動作を守りながら、UI、導線、演出、レスポンシブ等を改善するときに使う。

## 最初に確認するもの

1. DESIGN-PRINCIPLES.mdとAI-GUIDE.md
2. 現在のソースと公開画面
3. 画面構成、問題データ、判定、進行、保存、画像リンク
4. ユーザーが触らないと指定した領域
5. 既存保存データの形式
6. 画像・CSS・外部モジュールの読み込み先

## 使用候補

- 改善対象に必要な共通資産だけ
- UI変更：edu-effects
- ロジック置換が明示的に必要な場合：edu-components
- ナビキャラ、音、報酬は別Skillも併用

## 手順

1. 壊してはいけない領域を保護対象として明文化する。
2. 公開画面とソースを照らし、実際に使われている入口・単元・画像・保存キーを特定する。
3. 問題データ・正答・判定ロジック・問題数・保存は、依頼に必要でない限り変更しない。
4. 改善対象と変更ファイルを限定する。
5. 共通部品を導入する場合も既存挙動との互換性を優先する。
6. 全面書き換えをする場合も、画面・UI・演出・ロジック・データを分けて置き換える。
7. 開始画面の選択、学習、正解、不正解、つまずきからの脱出、結果、ホーム復帰を確認する。
8. 答えを見る機能を追加する場合は、正答・マスター達成と別の状態で保存する。
9. 既存保存データ、新規状態、リロード後の状態を確認する。
10. タブレット横向きの1画面で問題・観察・主要操作を確認する。
11. 画像リンク、文字切れ、白いちらつき、レイアウトシフト、コンソールエラーを確認する。
12. final-reviewを実行する。

## 完了条件

- 保護対象を変更していない。
- 正解して進め、不正解や長い迷いでも停止しない。
- ヒント・解説・答えを見る・再挑戦など、必要な脱出口がある。
- ホーム復帰と再スタートができる。
- 問題数・正答・学習順序が意図せず変わっていない。
- 既存保存データとリロード後の状態が壊れていない。
- タッチとマウスで操作できる。
- 補助資産の失敗で学習本体が止まらない。
