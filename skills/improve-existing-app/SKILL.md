# Improve Existing App

## いつ使うか

既存教材の学習内容と動作を守りながら、UI、導線、演出、レスポンシブ等を改善するときに使う。

## 最初に確認するもの

1. `DESIGN-PRINCIPLES.md`と`AI-GUIDE.md`
2. 現在の画面構成、問題データ、判定、進行、保存、ナビゲーション
3. ユーザーが触らないと指定した領域
4. 既存保存データの形式

## 使用候補

- 改善対象に必要な共通資産だけ
- UI変更: `edu-effects`
- ロジック置換が明示的に必要な場合: `edu-components`
- ナビキャラ、音、報酬は別Skillも併用

## 手順

1. 壊してはいけない領域を保護対象として明文化する。
2. 問題データ・正答・判定ロジックは依頼に必要でない限り変更しない。
3. 改善対象と変更ファイルを限定する。
4. 共通部品を導入する場合も既存挙動との互換性を優先する。
5. 全面書き換えより、小さく追跡可能な変更を優先する。
6. 開始→出題→正解→不正解→次問→結果→ホーム復帰を確認する。
7. 既存保存データとリロード後の状態を確認する。
8. `final-review`を実行する。

## 完了条件

- 保護対象を変更していない。
- 正解して進め、不正解でも停止しない。
- ホーム復帰と再スタートができる。
- 問題数・正答・学習順序が意図せず変わっていない。
- タッチとマウスで操作できる。
- 補助資産の失敗で学習本体が止まらない。
